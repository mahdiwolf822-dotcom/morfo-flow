# Morfo Flow

سیستم اتوماسیون اختصاصی کسب‌وکار — بخشی از مجموعه Morfo (themorfo.ir).
لندینگ پیج + سیستم ورود/ثبت‌نام (ایمیل و گوگل) + داشبورد مشتری + پنل ادمین، همه روی زیرساخت رایگان Cloudflare.

## ساختار پوشه‌ها
```
morfo-flow-project/
├── public/                          ← فایل‌های سایت
│   ├── index.html                   ← لندینگ پیج + فرم درخواست مشاوره
│   ├── login.html                   ← ورود / ثبت‌نام (ایمیل + گوگل)
│   ├── dashboard.html               ← داشبورد مشتری
│   ├── admin.html                   ← پنل مدیریت داخلی (محافظت‌شده با توکن)
│   └── assets/fonts/                ← فونت وزیرمتن (self-hosted)
├── functions/
│   ├── _lib/
│   │   ├── auth.js                  ← هش رمز عبور + نشست‌های امضاشده
│   │   └── telegram.js              ← اطلاع‌رسانی به تلگرام
│   └── api/
│       ├── request.js               ← فرم لندینگ → ذخیره در D1
│       ├── leads.js                 ← لیست یکپارچه همه درخواست‌ها (برای ادمین)
│       ├── auth/{signup,login,logout,me,google-start,google-callback}.js
│       └── dashboard/requests.js    ← درخواست‌های هر مشتری از حساب خودش
├── db/schema.sql                    ← ساختار جدول‌های D1
├── wrangler.toml
└── README.md
```

## استقرار روی Cloudflare Pages (رایگان) — قدم به قدم

1. یک ریپازیتوری گیت‌هاب بساز و این پوشه رو push کن.
2. Cloudflare Dashboard → **Workers & Pages → Create → Pages → Connect to Git**
3. تنظیمات build: Build command خالی، Build output directory = `public`
4. ساخت دیتابیس:
   ```
   wrangler d1 create morfo-db
   wrangler d1 execute morfo-db --file=./db/schema.sql
   ```
   شناسه‌ای که برمی‌گرده رو در `wrangler.toml` جای `REPLACE_WITH_YOUR_D1_DATABASE_ID` بذار (یا از Dashboard دیتابیس رو به پروژه Pages وصل کن).
5. در **Settings → Environment Variables** این‌ها رو اضافه کن (توضیح هرکدوم در `wrangler.toml` هست):
   - `ADMIN_TOKEN`، `SESSION_SECRET` (الزامی)
   - `GOOGLE_CLIENT_ID`، `GOOGLE_CLIENT_SECRET`، `GOOGLE_REDIRECT_URI` (برای ورود با گوگل — پایین توضیح داده شده)
   - `TELEGRAM_BOT_TOKEN`، `TELEGRAM_CHAT_ID` (اختیاری — برای اعلان درخواست جدید)
6. دیپلوی مجدد بزن — سایت آماده‌ست.

همه‌چیز داخل پلن رایگان Cloudflare Pages می‌گنجه (Functions تا ۱۰۰,۰۰۰ درخواست/روز، D1 تا ۵ گیگابایت و ۵ میلیون خواندن/روز).

## ورود با گوگل
1. [Google Cloud Console](https://console.cloud.google.com/) → پروژه بساز
2. **APIs & Services → OAuth consent screen** (نوع External کافیه)
3. **Credentials → Create Credentials → OAuth Client ID** (نوع Web Application)
4. Authorized redirect URI: `https://themorfo.ir/api/auth/google-callback`
5. Client ID/Secret رو در Environment Variables بذار (بالا لیست شده)

## اطلاع‌رسانی به تلگرام
1. به [@BotFather](https://t.me/BotFather) پیام بده → `/newbot` → یک اسم و username بساز
2. توکنی که می‌ده رو به‌عنوان `TELEGRAM_BOT_TOKEN` ثبت کن
3. به [@userinfobot](https://t.me/userinfobot) پیام بده تا Chat ID خودتو بگیری → به‌عنوان `TELEGRAM_CHAT_ID` ثبت کن
4. یک بار به ربات تازه‌ساخته‌ات `/start` بزن (تا اجازه پیام‌دادن بهت رو داشته باشه)

اگه این دو متغیر رو تنظیم نکنی، سایت عادی کار می‌کنه، فقط اعلان تلگرام خاموش می‌مونه.

## معماری داده
همه درخواست‌ها — چه از فرم لندینگ (بدون حساب کاربری) چه از داشبورد مشتری (با حساب) — در یک جدول واحد D1 به اسم `requests` ذخیره می‌شن، با ستون `source` که منشأشون رو مشخص می‌کنه. پنل ادمین (`/admin.html` → `/api/leads`) هر دو نوع رو یکجا نشون می‌ده.

## پنل مدیریت
آدرس: `/admin.html` — با `ADMIN_TOKEN` وارد شو. آمار روزانه/هفتگی، جستجو، لیست همه درخواست‌ها، و حالا **تغییر وضعیت هر درخواست** (در انتظار بررسی / در حال انجام / تکمیل‌شده) مستقیم از داخل کارتش رو داره.

⚠️ این یک احراز هویت ساده با توکنه، نه لاگین کامل. وقتی پرداخت وارد بشه، باید جایگزینش کنیم با چیزی جدی‌تر (مثل Cloudflare Access).

## داشبورد مشتری
آدرس: `/dashboard.html` — بعد از ورود/ثبت‌نام، مشتری‌ها اینجا می‌رسن (نه پنل ادمین). می‌تونن درخواست اتوماسیون ثبت کنن و وضعیت درخواست‌های قبلی‌شون رو ببینن.

## فونت
از بین ۷ فونتی که فرستادی، **وزیرمتن (Vazirmatn)** انتخاب و کامل self-host شد (بدون وابستگی به CDN بیرونی — سریع‌تر و پایدارتر):
- بیشترین طیف وزن (Thin تا Black) برای سلسله‌مراتب تایپوگرافی یک SaaS
- مجوز متن‌باز SIL OFL، بدون نگرانی حقوقی برای استفاده تجاری

⚠️ IRANSans و Yekan که فرستادی فایل لایسنس نداشتن؛ این دو سنتاً برای استفاده تجاری نیاز به خرید لایسنس دارن، پس عمداً استفاده نشدن. اگه لایسنس تجاری IRANSans رو داری، بگو جایگزینش کنیم.

## تست و کیفیت کد
هر تغییری قبل از تحویل با مجموعه‌ای تست خودکار بررسی می‌شه: رندر واقعی صفحات در مرورگر (Playwright)، کلیک روی فرم‌ها، شبیه‌سازی پاسخ سرور، و اجرای واقعی منطق پایگاه‌داده روی SQLite — نه فقط حدس.

## بهبودهای حرفه‌ای این نسخه
- **دسترسی‌پذیری (Accessibility)**: تب‌های ورود/ثبت‌نام حالا نقش‌های ARIA درست دارن (صفحه‌خوان‌ها می‌فهمن کدوم تب فعاله)، پیام‌های خطا/موفقیت با `aria-live` فوری به صفحه‌خوان اعلام می‌شن، دکمه‌های آیکون‌فقط (مثل چشم رمز عبور) برچسب دارن.
- **SEO و اشتراک‌گذاری**: فاویکون اختصاصی، متاتگ‌های Open Graph برای نمایش درست لینک در تلگرام/واتساپ، `robots.txt` (که پنل ادمین و داشبورد رو از ایندکس گوگل مستثنی می‌کنه) و `sitemap.xml`.
- **امنیت**: به‌روزرسانی وضعیت درخواست، توکن ادمین رو از هدر می‌گیره نه از آدرس URL (بر خلاف لیست‌گیری که هنوز از query param استفاده می‌کنه) — یعنی در تاریخچه مرورگر یا لاگ سرور ثبت نمی‌شه.

## موتور اتوماسیون خودساز (تغییر اساسی مدل کسب‌وکار)
قبلاً مشتری درخواست می‌داد و ما دستی براش می‌ساختیم — این مدل با ۱۰۰۰ مشتری اصلاً جواب نمی‌ده. الان **خود سایت** اتوماسیون رو برای مشتری می‌سازه:

1. مشتری وارد داشبورد می‌شه، یک ربات تلگرام رایگان (از @BotFather) می‌سازه و توکنش رو وارد می‌کنه
2. سیستم **خودش** توکن رو اعتبارسنجی می‌کنه، ربات رو با وبهوک خودمون وصل می‌کنه (`setWebhook`)، و همه‌چیز فعال می‌شه — بدون دخالت دستی ما
3. مشتری قانون‌های «کلیدواژه → پاسخ» تعریف می‌کنه (مثلاً «قیمت» → «قیمت‌ها از ۱۰۰ تومن شروع می‌شه»)
4. وقتی کسی به ربات مشتری پیام می‌ده، Cloudflare Function ما (`functions/api/bot/[automationId].js`) پیام رو می‌گیره، قانون منطبق رو پیدا می‌کنه، و خودکار جواب می‌ده

**مدل رایگان/پولی**: نسخه رایگان هر کاربر رو به ۱ ربات و ۳ قانون محدود می‌کنه (در `functions/_lib/plans.js`). وقتی به سقف برسه، رابط کاربری خودش دکمه‌ها رو غیرفعال می‌کنه و پیام ارتقا نشون می‌ده — این‌جا دقیقاً جاییه که بعداً درگاه پرداخت وصل می‌شه (ستون `plan` در جدول `users` از `free` به `pro` تغییر کنه، محدودیت‌ها خودکار برداشته می‌شن).

**امنیت**: هر وبهوک یک `secret_token` اختصاصی داره که موقع `setWebhook` تنظیم می‌شه؛ اگه درخواستی این هدر رو نداشته باشه یا اشتباه باشه، رد می‌شه (جلوی جعل پیام رو می‌گیره).

فایل‌های کلیدی:
- `functions/_lib/telegram.js` — تعامل با Telegram Bot API (اعتبارسنجی توکن، وصل کردن وبهوک، ارسال پیام)
- `functions/_lib/matcher.js` — منطق تطبیق کلیدواژه (تست‌پذیر و مستقل)
- `functions/api/automations.js` + `automations/[id].js` + `automations/[id]/rules*` — مدیریت اتوماسیون‌ها و قوانین
- `functions/api/bot/[automationId].js` — همون وبهوکی که تلگرام بهش پیام می‌فرسته

## کانال‌های پشتیبانی‌شده (چندکاناله شد)
یک اتوماسیون دیگه فقط تلگرام نیست:
- **تلگرام** — همونی که بود؛ نیاز به توکن از BotFather.
- **ویجت وب‌سایت** (جدید) — بدون نیاز به هیچ توکن یا تاییدی. مشتری فقط اسم کسب‌وکارش رو می‌ذاره، ما یک تکه کد بهش می‌دیم (`public/widget.js`) که قبل از `</body>` سایتش می‌ذاره. یک حباب چت شناور (با Shadow DOM، بدون تداخل با استایل سایت میزبان) ظاهر می‌شه و از همون قوانین «کلیدواژه → پاسخ» استفاده می‌کنه. Endpoint عمومیش (`functions/api/widget/[automationId].js`) با CORS باز طراحی شده چون از دامنه‌های دلخواه صدا زده می‌شه.
- **اینستاگرام و واتساپ** — در رابط کاربری به‌عنوان «به‌زودی» غیرفعال نشون داده می‌شن. این دو برخلاف تلگرام و ویجت، نیاز به تایید رسمی کسب‌وکار از متا (فیسبوک) دارن که یک پروسه بیرون از کنترل ماست؛ کدشون رو وقتی تایید گرفتیم اضافه می‌کنیم، نه زودتر (تا چیز غیرکارکردی تحویل ندیم).

## صفحه قیمت‌گذاری
`public/pricing.html` — مقایسه پلن رایگان و حرفه‌ای، با FAQ. دکمه «ارتقا به حرفه‌ای» داخل داشبورد هم به همین صفحه لینک می‌شه.

## پاسخ هوشمند با کلید AI خودِ مشتری — چند ارائه‌دهنده با سوییچ هوشمند (BYOK)
این بخش دقیقاً معماری «ما زیرساخت می‌دیم، مشتری با کلید خودش استفاده می‌کنه» رو پیاده می‌کنه، و محدود به یک ارائه‌دهنده نیست:

**۶ ارائه‌دهنده پشتیبانی می‌شن**: Gemini، OpenAI، Claude (Anthropic)، Groq، OpenRouter، DeepSeek — مشتری کلید هرکدوم رو که داره (یا رایگان می‌گیره) وصل می‌کنه.

- هر مشتری می‌تونه هم‌زمان چند کلید وصل کنه (مثلاً هم Gemini هم Groq) و با **یک کلیک روی چیپ هرکدوم** (`public/dashboard.html` → provider-grid) بین‌شون سوییچ کنه — همون‌جوری که خواسته شد: «حالت سوییچ حرفه‌ای»
- **حالت هوشمند (Smart Fallback)**: وقتی ۲+ ارائه‌دهنده وصل باشه، یک toggle ظاهر می‌شه؛ اگه روشن باشه و ارائه‌دهنده فعال جواب نداد (اتمام اعتبار، قطعی)، خودکار به ترتیب اولویت سراغ بقیه می‌ریم تا یکی جواب بده (`functions/_lib/reply-resolver.js`)
- قبل از ذخیره هر کلید، با یک پیام تست واقعی اعتبارسنجی می‌شه؛ کلید غلط فوری رد می‌شه
- کلید هرگز خام ذخیره نمی‌شه — با AES-GCM رمزنگاری می‌شه (`functions/_lib/crypto-secrets.js`)؛ کلید رمزنگاری سرور (`ENCRYPTION_KEY`) هیچ‌وقت به فرانت‌اند نمی‌ره
- هزینه هر پیام مستقیم بین مشتری و ارائه‌دهنده حساب می‌شه، نه از جیب Morfo Flow
- اضافه کردن ارائه‌دهنده هفتم فقط یعنی یک تابع جدید در `functions/_lib/ai.js` — بقیه سیستم (رمزنگاری، سوییچ، fallback، UI) خودکار باهاش کار می‌کنه

فایل‌های کلیدی این بخش:
- `functions/_lib/ai.js` — تماس با هرکدوم از ۶ API (فرمت‌های متفاوت: OpenAI-style برای ۴ تا، فرمت خاص Gemini، فرمت خاص Anthropic)
- `functions/_lib/reply-resolver.js` — منطق سوییچ + زنجیره fallback
- `functions/api/automations/[id]/ai/{credentials,active,fallback,instructions}.js` — مدیریت کلیدها، سوییچ، حالت هوشمند، و دستورالعمل لحن

⚠️ نیاز به یک متغیر محیطی: `ENCRYPTION_KEY` (یک رشته تصادفی طولانی، مثلاً با `openssl rand -hex 32`) در Cloudflare Environment Variables.

## تست زنده اتوماسیون از داخل داشبورد
هر اتوماسیون یک جعبه «تست زنده» داره که بدون نیاز به تلگرام واقعی یا نصب ویجت، رفتار قانون‌ها و AI (شامل زنجیره fallback) رو نشون می‌ده (`functions/api/automations/[id]/test.js`). پیام‌های تستی در آمار (`interactions`) ثبت نمی‌شن تا آمار واقعی رو خراب نکنن.

## آمار استفاده
هر کارت اتوماسیون یک خط آمار داره: چند پیام واقعی جواب داده شده، چندتاش با قانون بوده، چندتاش با AI، و چندتا بی‌پاسخ مونده. این از جدول `interactions` میاد که هر پیام واقعی (نه تستی) توش لاگ می‌شه.

## امنیت
- endpoint عمومی ویجت (`/api/widget/:id`) محدودیت نرخ داره: هر بازدیدکننده حداکثر ۱۵ پیام در دقیقه (`functions/_lib/rate-limit.js`, روی همون D1 بدون نیاز به KV)
- کلیدهای API مشتری با AES-GCM رمزنگاری می‌شن، نه متن خام
- توکن ادمین برای عملیات نوشتن (تغییر وضعیت) از هدر گرفته می‌شه نه URL

## پس‌زمینه WebGL صفحه ورود (ارتقای تدریجی)
صفحه `login.html` حالا یه پس‌زمینه سه‌بعدی واقعی با Three.js داره (ابر ذرات درخشان با عمق و چرخش ملایم دوربین) که مستقیم از CDN (بدون نیاز به React یا بیلد) لود می‌شه. الهام‌گرفته از سبک [ThreeUI](https://threeui.com) (نه کدشون — چون React-based و بخشیش پولیه، با معماری استاتیک ما جور درنمیاد).

⚠️ **طراحی defensive**: اگه CDN در دسترس نباشه (اینترنت قطع، فایروال)، همون پس‌زمینه canvas دوبعدی قبلی (که قبلاً تست و تایید شده) دست‌نخورده باقی می‌مونه — کاربر هیچ‌وقت با صفحه خالی یا خراب مواجه نمی‌شه. این رفتار با تست مخصوص (`test_webgl_fallback`) هم تایید شده.

## اینستاگرام (رسمی — نه دور زدن قوانین متا)
مشتری با یک کلیک حساب اینستاگرام **Business/Creator** خودش (باید به یک پیج فیسبوک وصل باشه) رو از طریق OAuth رسمی متا وصل می‌کنه. بدون توکن دستی، بدون کتابخونه غیررسمی.

**چرا این مسیر امن‌تره از هر روش دیگه‌ای**: کتابخونه‌های غیررسمی که حساب شخصی اینستاگرام رو با شبیه‌سازی می‌کنن، قوانین متا رو نقض می‌کنن و مرتب حساب‌ها رو برای همیشه بن می‌کنه — یعنی هر مشتری‌ای که وصل کنه، بالقوه کل کسب‌وکارش رو روی اینستاگرام از دست می‌ده. این نسخه فقط از API رسمی Graph استفاده می‌کنه.

**راه‌اندازی (یک‌بار، فقط توسط خودت)**:
1. یک اپ در [Meta for Developers](https://developers.facebook.com/) از نوع Business بساز
2. دسترسی `instagram_manage_messages` و `pages_messaging` رو ازش با App Review بگیر (چند روز تا ۲ هفته طول می‌کشه؛ تا قبل از تایید، فقط با حساب‌های تست خودت کار می‌کنه)
3. متغیرهای محیطی رو در Cloudflare تنظیم کن: `INSTAGRAM_APP_ID`، `INSTAGRAM_APP_SECRET`، `INSTAGRAM_REDIRECT_URI` (=`https://themorfo.ir/api/instagram/oauth-callback`)، `INSTAGRAM_WEBHOOK_VERIFY_TOKEN` (یک رشته دلخواه که خودت انتخاب می‌کنی)
4. در تنظیمات وبهوک اپ، آدرس `https://themorfo.ir/api/instagram/webhook` رو با همون verify token ثبت کن

فایل‌های کلیدی: `functions/_lib/instagram.js` (تعامل با Graph API)، `functions/api/instagram/{oauth-start,oauth-callback,webhook}.js`

⚠️ توکن دسترسی حدود ۶۰ روز اعتبار داره و نیاز به تازه‌سازی دوره‌ای داره — این بخش (renewal خودکار با Cloudflare Cron Triggers) هنوز ساخته نشده، در لیست قدم بعدی هست.

## بله (Bale) — کانال ایرانی جدید
بله یک Bot API دقیقاً مثل تلگرام داره (`tapi.bale.ai` به‌جای `api.telegram.org`، همون متدها). به همین خاطر از همون زیرساخت تلگرام استفاده می‌کنه — فقط `channelType: 'bale'` رو انتخاب کن، توکن ربات بله رو بچسبون، تمام. کدش در `functions/_lib/telegram.js` (تابع‌ها حالا `baseUrl` می‌گیرن) و `functions/api/bot/[automationId].js` مشترکه.

## روبیکا و ایتا — بررسی شد، هنوز اضافه نشده
- **روبیکا**: یک Bot API رسمی داره (`botapi.rubika.ir`) و متد ارسال پیام (`sendMessage`) کامل مستند شده. اما فرمت دقیق پیام‌های **ورودی** (وقتی مشتری پیام می‌ده، وبهوک با چه ساختاری بهمون خبر می‌ده) رو نتونستم از مستندات عمومی ۱۰۰٪ تایید کنم. به‌جای اینکه کد حدسی بسازم که ممکنه بی‌صدا خراب باشه، ترجیح دادم صبر کنم تا با یه ربات واقعی تست کنیم و فرمت واقعی رو ببینیم.
- **ایتا**: چیزی که به اسم «بات» ایتا در دسترسه (Eitaayar) بیشتر برای **ارسال پیام به کانال/گروه** طراحی شده (مثل یک ابزار پست خودکار)، نه یک ربات مکالمه‌ای که به پیام تک‌تک مشتری‌ها جواب بده. برای اینکه اتوماسیون ما (که مبتنی بر «مشتری پیام می‌ده، ربات جواب می‌ده» است) روش کار کنه، این ابزار مناسب نیست — مگر اینکه بعداً بخوایم یه قابلیت جدا برای «ارسال خبرنامه به کانال» بسازیم.

## قدم بعدی پیشنهادی (ایده‌های باقی‌مانده)
- روبیکا: بعد از ساخت یه ربات واقعی و دیدن فرمت واقعی وبهوک، اضافه‌ش کنیم
- تازه‌سازی خودکار توکن اینستاگرام قبل از انقضای ۶۰ روزه (Cloudflare Cron Triggers)
- واتساپ: انتخاب بین Cloud API مستقیم یا یه BSP (360dialog/Twilio) برای Embedded Signup
- درگاه پرداخت (زرین‌پال) + منطق واقعی تغییر پلن از `free` به `pro`
- به‌روزرسانی کپی لندینگ پیج برای تاکید روی «همین الان رایگان بساز»
- آنبوردینگ تعاملی اول ورود (ویزارد ۳ مرحله‌ای)
- قالب‌های آماده قوانین بر اساس نوع کسب‌وکار (فروشگاه، کلینیک، آژانس...)
- Fallback هوشمند به انسان: وقتی AI/قوانین چند بار جواب ندادن، به تلگرام خودِ صاحب کسب‌وکار پیام بده
- Webhook خروجی برای مشتری‌های حرفه‌ای (اتصال به Google Sheets/CRM خودشون)
- ساعت کاری/روز تعطیل برای قانون‌ها
- چندزبانه‌سازی خودکار پاسخ AI بر اساس زبان پیام ورودی
- BYOK برای پنل پیامکی (مثل ملی‌پیامک/کاوه‌نگار) به همون سبک کلید AI
